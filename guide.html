  3. 분석을 시작하기 전에 지금 화면이 FE 포함 상태인지 먼저 확인합니다. 이 설정이 달라지면 뒤의 모든 비율이 달라집니다.

Executive View는 경영진 조회용 기본 화면입니다. 데이터 Upload·관리자 수정 같은 운영 기능이 숨겨진 상태로 표시됩니다.

각 팀의 전체 MH를 기준으로 업무 유형별 투입 비중을 봅니다. 업무분류는 일반 = 일반 + 하자보수, 견적 = 견적 + 영업으로 묶입니다. 일반 업무는 메인 그래프에서는 빠지지만 상세 데이터에는 포함됩니다.

이렇게 사용합니다

  1. 먼저 막대를 눈으로 비교합니다. 위 예시에서 A팀은 전체 MH 중 수행 70%, 지원 10%, 견적·영업 5%가 투입된 상태입니다.
  2. 막대의 특정 영역을 클릭합니다. 클릭한 팀·업무구분의 활동구분 Top 5가 열려, 그 MH가 실제로 어떤 업무에 쓰였는지 확인할 수 있습니다.
  3. 같은 창에 선택한 팀의 LOAD율이 함께 표시됩니다. 비율이 높다는 사실과 그 비율을 만든 활동을 한 번에 볼 수 있습니다.
  4. 다른 영역(지원·견적)을 클릭하면 같은 방식으로 해당 업무구분의 Top 5로 바뀝니다.
  5. 비교 관점을 바꾸려면 상단에서 기본순서 / 수행율 높은순 / 일반율 높은순 / 총 MH 높은순으로 정렬합니다.

이럴 때 씁니다. 특정 팀의 수행율이 다른 팀보다 눈에 띄게 낮으면, 그 팀의 지원 또는 일반 영역을 클릭해 어떤 활동이 MH를 가져갔는지부터 확인합니다. 기술기획팀은 이 화면에서 제외되지만 본부 ‘전체’ 합계에는 포함됩니다.

03

월별 WORKLOAD Trend

조회 대상을 전체 ↔ 개별 팀으로 전환

이렇게 사용합니다

  1. 기본은 전체 기준입니다. 1월부터 8월까지 수행율·지원율·견적율이 어떻게 움직였는지 먼저 봅니다.
  2. 상단 조회 대상을 개별 팀으로 바꿉니다. 전체에서 보이던 변화가 특정 팀에서 온 것인지, 여러 팀에 걸친 것인지 구분됩니다.
  3. 팀을 하나씩 바꿔가며 같은 구간을 비교합니다. 한 팀만 반대로 움직인다면 그 팀이 원인일 가능성이 큽니다.
  4. 원인을 찾았으면 팀별 WORKLOAD 화면으로 돌아가 해당 팀 막대를 클릭해 활동구분까지 확인합니다.

판단 기준. 수행율이 계속 낮아지면서 견적율이나 지원율이 올라가면 업무구성이 바뀌는 중입니다. 단월 등락과 구분하려면 최소 3개월 흐름을 봅니다. Trend는 월별 데이터가 2개월 이상 등록되어야 표시됩니다.

이렇게 사용합니다

  1. 기본 지표는 해당 Project MH ÷ 본부 전체 입력 MH × 100입니다. 본부 자원이 어디에 몰려 있는지 순서대로 보입니다.
  2. 상단에서 수행+지원 / 수행 / 지원으로 조회 방식을 바꿉니다. ‘수행’만 볼 때와 순위가 달라지는 Project는 지원 MH가 많이 들어간 Project입니다.
  3. 궁금한 Project의 막대를 선택하면 그 Project에 각 팀이 얼마나 투입되고 있는지 열립니다.
  4. 이때 팀별 투입률은 본부 전체가 아니라 해당 팀의 전체 MH 기준입니다. 예시의 34.2%는 A팀 전체 MH의 3분의 1이 이 Project에 들어갔다는 뜻입니다.

이럴 때 씁니다. 특정 팀의 투입률이 유독 높으면 그 Project가 팀 Capacity를 얼마나 점유하는지 판단하고, 다른 업무 지연 여부를 함께 확인합니다.

05

수행 프로젝트별 누적 집계

Project 행을 선택해 월별 추이 확인

이렇게 사용합니다

  1. 8월을 조회 중이면 등록된 월까지의 수행 MH가 Project별로 누적되어 표시됩니다. 단월 화면과 달리 투입 규모의 총량을 봅니다.
  2. 구성비로 상위 Project를 먼저 확인합니다. 단월 비중은 낮아도 누적이 큰 Project가 실제 자원을 많이 쓴 Project입니다.
  3. Project 행을 선택하면 월별 수행 MH와 LOAD율이 아래에 펼쳐집니다.
  4. 월별 값이 계속 늘고 있는지, 특정 월에 몰렸다가 줄었는지를 보고 그 Project가 지금도 자원을 쓰고 있는지 판단합니다.

이렇게 이어서 봅니다. 누적이 큰데 최근 월 LOAD가 급감했다면 종료 단계일 수 있고, 반대로 최근 월이 급증했다면 앞의 Workload율 화면에서 어느 팀이 들어갔는지 확인합니다.

Management Insight

읽고 끝내지 않고 Drill-down의 출발점으로

화면 하단에서 주요 수치 변화를 Rule 기반으로 자동 요약합니다. 이상징후나 추가 확인이 필요한 영역을 빠르게 찾는 용도로 사용하고, 문장을 읽은 뒤에는 해당 팀 또는 Project 그래프로 이동해 원인을 확인합니다.

1수행 WORKLOAD 및 전월 대비 변화 → 변화가 크면 Trend에서 지속성 확인
2일반업무 비중이 가장 높은 팀 → 해당 팀 막대 클릭해 활동구분 Top 5 확인
3견적·영업 비중이 가장 높은 팀 → 수주 준비 부담인지 확인
4총 MH 전월 대비 증감 → 비율 변화가 분모 변화 때문인지 확인
5인건비·관리비 계획대비 증감
6재무 실적 미입력 여부 → 미입력은 0이 아니므로 판단 보류
7미분류 업무구분 발생 여부 → 원데이터 Mapping 확인 요청

조작 전에 확인할 6가지

미입력 ≠ 0

재무 실적이 입력되지 않으면 ‘미입력’으로 표시됩니다. 0으로 읽지 않습니다.

증감의 정의

모든 재무 증감은 ‘실적 − 계획’ 기준입니다.

누계 비교 기준

항목별로 실적이 연속 입력된 월까지를 계획과 동일기간으로 비교합니다.

FE 포함 여부

상단 Toggle 상태에 따라 WORKLOAD·Project 수치가 모두 달라집니다.

미분류 Warning

정의되지 않은 업무구분이 있으면 경고가 표시됩니다. 원데이터 Mapping 확인이 필요합니다.
